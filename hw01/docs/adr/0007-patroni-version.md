# ADR-0007. Закрепление версии Patroni (3.0.0)

## Контекст
Чекер (`hw01_check.py`, `check_ha`) считает кластер здоровым только если **все** члены из `GET /cluster` имеют `state == "running"`. Первая сборка стенда использовала свежий Patroni (4.1.5): кластер работал штатно, но в чекере
получилось `running 1 из 3` — раздел HA (2 балла) обнулялся. Причина в исходниках Patroni: в `patroni/utils.py::cluster_as_json` у новых версий состояние реплики подменяется на `replication_state` (`streaming`), а в старых отдаётся `state` (`running`). Проверено сравнением исходников: 2.1.7 и 3.0.0 — `'state': m.data.get('state', '')`;
3.0.4, 3.3.0, 4.0.7, 4.1.0 и 4.1.5 — `state = replication_state … or state` (версии 3.0.1–3.0.3 не проверялись, граница где-то между 3.0.0 и 3.0.4).

## Рассмотренные варианты
1. **Оставить Patroni 4.1.5** и принять потерю баллов HA.
2. **Править чекер** — чекер «тот самый», которым проверяет преподаватель; менять его нельзя и бессмысленно.
3. **Поставить перед REST API прокси, который переписывает `streaming → running`** (или иным образом подменить наблюдаемый ответ).
4. **Закрепить Patroni 3.0.0** (`ARG PATRONI_VERSION=3.0.0` в `docker/patroni/Dockerfile`).

## Выбор
Вариант 4. Patroni 3.0.0 работает с PostgreSQL 18.6: проверено в журнале отказоустойчивости — первичная инициализация, аварийный failover, `pg_rewind`, плановый switchover, `synchronous_mode`, отказ etcd, сетевой раздел (Э1–Э10). Версия — один build-аргумент: если проверку исправят, достаточно поменять его.

## Отвергнутая альтернатива и причина
**Прокси, подделывающий ответ (вариант 3), отвергнут принципиально**: он нужен только чтобы пройти проверку, а не чтобы система работала лучше — это фальсификация наблюдаемого состояния кластера, и подмена скрыла бы реальные проблемы в `/cluster`.
**Оставить 4.1.5 (вариант 1)** отвергнут как неоправданная потеря: поведение кластера одинаково, а несовпадение — в формате одного поля ответа.

## Цена выбора
- Релиз Patroni **январь 2023** — без исправлений и улучшений последних версий; официальная поддержка PostgreSQL 18 в нём не заявлена (на наших экспериментах работает, но на непроверенных сценариях гарантий нет).
- `patronictl` из 3.0.0 не импортируется с современным `ydiff` — пришлось закрепить `ydiff==1.2` (иначе `ImportError: cannot import name 'PatchStream'`).
- Артефакт чекера, а не особенность Patroni, определил версию в продакшен-образе. **Рекомендация:** сообщить преподавателю, что `state == "running"` для реплик не выполняется ни у одного из проверенных Patroni ≥ 3.0.4; после исправления чекера вернуться на актуальную версию.
