# ADR-0002. Способ хранения истории цен

## Контекст
Цена действует **на интервале времени** и имеет область действия: вся сеть (`chain`), регион или конкретная аптека; узкая область приоритетнее широкой. Контракт (`contract.v_price`) требует колонки `valid_from`, `valid_to`, `is_current`;
интервалы полуоткрытые `[valid_from, valid_to)`, у области не должно быть пересекающихся интервалов (I5) и должна быть ровно одна текущая версия (I6). Чекер (X08) проверяет, что на момент любой продажи нашлась действующая цена.

## Рассмотренные варианты
1. **Цена колонкой в `sku` с перезаписью** — просто, но истории нет; snapshot в позиции чека спасает отчёты, но не отвечает на «какая цена действовала в аптеке X 3 марта» и не даёт `valid_from/valid_to` для контракта.
2. **Журнал событий «цена изменена»** (append-only), интервалы вычисляются оконными функциями во view — компактно, но контракт требует хранимых `valid_to`/`is_current`, а запрет пересечения не выражается ограничением над журналом событий.
3. **Основная таблица с текущей ценой + отдельная таблица истории** (как для атрибутов SKU, ADR-0005) — для цен неудобно: поиск цены на произвольный момент превращается в `UNION` двух таблиц.
4. **SCD2 в одной таблице: строка = версия цены на интервале**, `EXCLUDE USING gist` против пересечений, частичный уникальный индекс против двух текущих версий.

## Выбор
Вариант 4: `catalog.price` (`price_scope`, `scope_bk`, `valid_from`, `valid_to`, `is_current`). I5 — `EXCLUDE USING gist (sku_id =, price_scope =, scope_bk =, tstzrange(valid_from, valid_to, '[)') &&)` (расширение `btree_gist`).
I6 — `CREATE UNIQUE INDEX … WHERE is_current`. `is_current` — **хранимый** флаг: `CHECK (is_current OR valid_to IS NOT NULL)`, а при вставке новой открытой версии триггер закрывает предыдущую.
В контракте цена вычислена не через `now()`, а читает флаг — иначе отпечатки мастера и реплики разошлись бы на строке, интервал которой закончился между двумя чтениями.

## Отвергнутая альтернатива и причина
Вариант 3 (текущая + история в отдельной таблице) отвергнут для цен: основной запрос предметной области — «цена на момент T» — должен решаться одним индексным обращением к одной таблице, а при двух таблицах каждое чтение превращается в `UNION`,
и граница «текущая/историческая» перемещается при каждой смене цены. Для атрибутов SKU, где основной запрос — «текущее состояние», тот же вариант, наоборот, выбран (ADR-0005).

## Цена выбора
- **Запись дороже**: смена цены = `INSERT` новой версии + `UPDATE` предыдущей (закрытие), и обе операции проходят через gist-индекс `EXCLUDE`; индекс больше и медленнее btree.
- `is_current` — **денормализация**: её согласованность с `valid_to` держат CHECK и триггер, а не вывод. Версия с `valid_to` в будущем (запланированная цена) допустима как текущая (C11).
- Приоритет областей (аптека > регион > сеть) **не выражен в БД** — его применяет потребитель (в `seed.py` — `price_at`, в чекере — X08). Значение `scope_bk` для региона — название региона как в `pos.pharmacy.region`, т.е. ссылка на справочник другого сервиса по значению, а не по ключу.
- Число строк растёт как (SKU × области × смены цены): сид даёт 3 081 версию на 650 SKU.
